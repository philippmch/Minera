# LOG LTL filter parity contract

The companion in `include/minera/log_ltl_filter.hpp` covers the six public functions of `pm4py.algo.filtering.log.ltl.ltl_checker` from PM4Py 2.7.22, pinned commit `0715c31f3f1d85924107d6aa5329806db69df899`. Public signatures, docs, enums, complete public observations and opaque hashes were used. Reference implementation source, AST, bytecode and private state were not inspected. Existing convenience LTL filtering remains unchanged.

The four native filter entry points are `filter_log_ltl_eventually_follows`, `filter_log_ltl_next`, `filter_log_ltl_four_eyes` and `filter_log_ltl_different_persons`. Their selectors, labels, collection, polarity and temporal controls use ordinary typed EventAttribute carriers. Literal empty attribute/resource/timestamp names remain literal. Missing selected cells are ignored; unhashable selector errors are lazy on actual event lookup. Ordinary null, booleans, exact large integers, floats, bytes, datetime, UUID, list, tuple, dictionary and frozen-set selected values are represented. Direct equality with NativeNA raises the retained ambiguous-boolean error, while NaN and NaT do not match themselves in direct activity comparisons. Resource collection uses hashable set semantics: empty string/null are actual values, the NativeNA singleton coalesces, distinct NaN cells remain distinct, and list/dictionary resources raise the captured unhashable-type error.

Eventually follows accepts an iterable pattern, including empty and single-element patterns. It selects the first strictly increasing forward occurrence of each requested value and stops at the first completed witness. Timed selection requires both a truthy enable flag and truthy supplied boundaries. Nonempty boundaries with an omitted/false flag remain inactive; absent, None or empty boundaries leave timestamps unread even when the flag is true. After an activity witness exists, active timing reads the raw trace prefix of pattern length and compares consecutive prefix-event timestamp differences. It uses those prefix timestamps even when noise or an earlier duplicate moves activity matches later in the trace. A single-value pattern does not need a timestamp. Datetime timestamp conversion uses floating epoch seconds before subtraction, retaining the observed microsecond rounding behavior and offset normalization. Naive timestamp conversion uses the process local timezone, consistent with the public runtime metadata retained in each capture. Next filtering checks actual consecutive event positions and supports repeated or equal labels. It does not activate timestamp controls. Four-eyes requires both selected resource sets to be nonempty: positive selects disjoint sets and negative selects overlapping sets. Traces missing either side belong to neither result. Different-persons selects more than one distinct matching resource; its negative includes vacuous cases. Neither resource filter activates temporal controls.

The typed helper results `log_ltl_timestamp_list_is_ge` and `log_ltl_timestamp_list_is_le` preserve the observed bool values. They compare `a[i]` against `b[i][0]` and `b[i][1]`, respectively, with inclusive interval endpoints. They iterate the length of a, ignore an unused b tail, and return false immediately on the first violated endpoint. Empty a returns true. A malformed later bound can remain unread. Scalar sequences, missing bounds, ordinary None/NA cells and datetime awareness mismatch preserve the retained diagnostic and lazy ordering. Exact large-integer comparisons avoid floating conversion.

Every returned result retains full log attributes, extensions, classifiers, global scopes, properties, trace attributes/properties, event values and ordering. Public results alias source traces; the native value ABI copies complete retained values and does not claim Python object identity. All retained source and control snapshots are unchanged on both success and error. Mutable primary overloads expose the honest public source contract, and const conveniences copy the source explicitly. Native-only controls additionally exercise legacy first-class activity/resource projections, custom source roles, independent event case fields, input order, context and const-copy isolation.
